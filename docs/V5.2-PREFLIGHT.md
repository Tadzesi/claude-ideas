## A.2.7 Tools Decision Justification (READ FIRST — STOP IF DISAGREE)

The original `agent-roles.json` granted these tool sets:

| Agent       | JSON `tools.allowed`        | New v5.2 frontmatter `tools` |
|-------------|-----------------------------|------------------------------|
| Explore     | Glob, Grep, Read, **Bash**  | Glob, Grep, Read             |
| Citation    | Grep, Read                  | Grep, Read                   |
| Security    | Grep, Read, **Bash**        | Grep, Read, Glob             |
| Performance | Grep, Read                  | Grep, Read, Glob             |
| Pattern     | Glob, Grep, Read            | Glob, Grep, Read             |

**Bash removed** from Explore + Security:
- Read-only research never needs shell execution. Original use case was
  "shell-out grep/find" — Grep+Glob fully cover it.
- Bash widens attack surface (could touch git, install, network). Tightening
  the allowlist matches Anthropic's `safe-researcher` example verbatim
  (`tools: Read, Grep, Glob, Bash` — but their example explicitly notes
  "The subagent can't edit files, write files, or use any MCP tools";
  we go one step further by also dropping Bash since we don't need shell).
- **Anthropic ref:** https://code.claude.com/docs/en/sub-agents#available-tools

**Glob added** to Security + Performance:
- Original JSON denied them Glob, but they need pattern-based file
  enumeration (e.g. find all `*Auth*.cs`, find all migration scripts).
- Without Glob they'd have to lean on Bash. Adding Glob and dropping Bash
  is a net narrowing of capability.

**No agent gets Write/Edit/Bash/WebFetch/WebSearch/MCP** in v5.2:
- Research is strictly read-only. Findings flow back to main thread; main
  thread (orchestrator) does any writes.
- If future security agent needs CVE lookup, add via `mcpServers`
  (CVE/NVD MCP), not WebFetch.

> **STOP if you disagree with Bash removal.** This is the only tool decision
> that materially diverges from the JSON. If you want Bash kept on Explore
> or Security, say so before Phase B starts.

```markdown
## Specialist Selection Rules

Always spawn (every iteration of every research session):
- @research-explore   — file discovery, architecture mapping

Conditionally spawn based on detected keywords + complexity score:

| Subagent              | Spawn when (any condition true)                                              |
|-----------------------|------------------------------------------------------------------------------|
| @research-security    | keywords: security, authentication, authorization, encryption, vulnerability,|
|                       | payment, credential, password, token  OR  complexity >= 15                   |
| @research-performance | keywords: performance, slow, optimization, bottleneck, scalability, latency, |
|                       | throughput, caching  OR  complexity >= 12                                    |
| @research-pattern     | keywords: pattern, convention, like other, match existing, consistent        |
|                       | OR  strategy in {broad, comprehensive}                                       |

Strategy → default cohort:
- Narrow:        explore + citation                              (2 subagents)
- Broad:         explore + citation + pattern + (1 specialist)   (3-4)
- Comprehensive: explore + citation + security + performance + pattern (5)

Source: `.claude/config/orchestration-config.json#agent_cohort_rules`.
```

### Section 2: Orchestration Flow rewrite (~50 lines, replaces current lines 102-115)

```markdown
## Orchestration Flow

Iteration 1 (parallel spawn — single message with multiple Task tool
invocations, one per subagent):

  Task(subagent_type: "research-explore",   prompt: <scope-specific>)
  Task(subagent_type: "research-citation",  prompt: <scope-specific>)
  Task(subagent_type: "research-{security|performance|pattern}", ...)
                                            (per Selection Rules above)

Wait for all SubagentStop events (Anthropic auto-handles this when Task
calls are batched in one message).

Gap analysis (main context):
- Compare aggregated subagent summaries against
  `orchestration-config.json#convergence_settings`:
    min_coverage: 0.70, min_confidence: 0.80, max_unresolved_conflicts: 2.
- If converged → proceed to Aggregation.
- If gaps → Iteration 2 with refinement spawns targeted at the gap.

Iterations 2-4: spawn refinement subagents per detected gap. Stop when:
- convergence reached, OR
- max iterations (4) hit, OR
- no new findings between two consecutive iterations.

Aggregation (main context):
- Dedupe similar findings (similarity >= 0.85).
- Resolve conflicts (prefer higher-confidence source).
- Prioritise by severity (Critical/Important/Informational).
- Render report per template in `research-adapter.md`.

> **Why orchestration runs in main context:** Anthropic subagents cannot
> spawn other subagents (https://code.claude.com/docs/en/sub-agents#limitations).
> Iteration loop, gap analysis, and aggregation all live in the main thread.
```
