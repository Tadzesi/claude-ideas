## F.6 Anthropic alignment

**PASS.**

All 5 subagents have:
- `name`: lowercase + hyphens, unique (research-citation, research-explore,
  research-pattern, research-performance, research-security).
- `description`: pushy ("Use proactively...", "ALWAYS invoked..."), names
  triggers + cohort role + return value.
- `tools`: comma-separated valid Anthropic internal tool names. Every
  agent uses Read+Grep (and Glob where appropriate). No Write/Edit/Bash
  on any agent. Citation has only Read+Grep (no Glob — narrowest set).
- `model`: in {haiku, sonnet}. Routing is per-role: haiku for fast
  exploration / pattern / citation, sonnet for deep security / performance
  analysis.
- `color`: in valid Anthropic UI color set (blue, purple, green, red,
  orange).

No subagent declares it spawns another subagent. The grep that surfaced
"invoke other subagents" matches the Constraints sections that EXPLICITLY
DENY this:
> "Do not invoke other subagents (Anthropic limit:
>  https://code.claude.com/docs/en/sub-agents#limitations)."

This is the inverse of a false claim — it's an explicit honest constraint
citing the Anthropic source.

Orchestration (Task tool spawn, gap analysis, iteration loop, citation
index persistence, aggregation) lives in `prompt-research/SKILL.md`
(main thread), per the Anthropic limitation:
> "Subagents cannot spawn other subagents. If your workflow requires
> nested delegation, use Skills or chain subagents from the main
> conversation."  
> — https://code.claude.com/docs/en/sub-agents#limitations

## F.9 Externally readable

**PASS.**

A new developer reading these 5 files in order:

1. `README.md` — learns the repo offers 3 commands, that
   `/prompt-research` uses 5 real subagents in parallel via Task tool.
2. `CLAUDE.md` — learns interaction protocol (SK input / EN internals
   / SK output, Plan-First, Memory Recall, Never Auto-Execute).
3. `.claude/skills/prompt-research/SKILL.md` — learns the orchestrator
   logic: Specialist Selection Rules (always-spawn cohort + conditional
   triggers), Orchestration Flow (explicit Task tool spawn pattern,
   gap analysis, aggregation), Performance Expectations.
4. `.claude/agents/research-explore.md` — learns one specific subagent:
   what it does (file discovery, architecture mapping), what tools it
   uses (Read, Grep, Glob), what it returns, what constraints it honours.
5. `.claude/library/research-adapter.md` — learns Phase 0 specifics for
   research prompts: complexity scoring, strategy selection, clarifying
   questions, structured output template.

After these 5 files, the reader knows:
- WHERE the orchestration lives (main thread, in SKILL.md)
- WHY it lives there (Anthropic subagent nesting limit, cited)
- HOW subagents are spawned (Task tool, single message multiple calls)
- WHAT each subagent does (frontmatter description + body)
- WHEN each subagent is invoked (Selection Rules in SKILL)
- HOW Phase 0 differs for research vs other commands (research-adapter)

No "wait, where is the spawning logic?", no "this JSON config is
unused", no "this file says Haiku but has no frontmatter."
